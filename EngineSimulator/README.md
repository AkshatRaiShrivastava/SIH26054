# UAV Simulation & Replay

This repository contains a lightweight Python simulation of a medium‑altitude long‑endurance (MALE) UAV ISR sortie.  It models engine physics, stage‑by‑stage flight, fault injection, and an endurance/degradation scenario, and provides a replay engine that reads the recorded telemetry without recomputing physics.

## Repository layout
```
files/
├── mission_simulator.py   # Core simulator, includes endurance helper
├── mission_stages.py      # Stage definitions and environment presets
├── physics_model.py       # Pure physics calculations (expected values)
├── replay_engine.py      # Reads a saved mission JSON and replays it
├── demo_mission.json     # Example output generated by the demo script
├── expected_values_reference.csv  # Reference dataset
├── datasets/              # Versioned JSON datasets selectable in the UI
├── missions/              # JSON missions saved by the UI
└── frontend/              # Flask API and realtime browser UI
```

## Running the simulation (endurance scenario)
The demo script in `mission_simulator.py` runs a full mission with:
* a hot‑high‑altitude environment,
* endurance wear enabled (3 % drift per hour),
* an oil‑pressure fault injected halfway through the loiter stage.

```bash
python3 mission_simulator.py
```
The script will:
1. Generate telemetry for each second of the flight.
2. Save the mission to `demo_mission.json` in the same directory.
3. Print a short summary, a sample row before the fault, a sample row during the fault, and the event log.

## Replaying a saved mission
To verify that the replay engine reads the stored data (instead of recomputing physics), run:
```bash
python3 replay_engine.py
```
The demo in `replay_engine.py` will:
* Load `demo_mission.json`.
* Seek to a time inside the fault window and display the state.
* Advance a few frames at 10× speed, printing the current stage.
* Print stage‑boundary timestamps useful for UI timelines.

## Custom runs
You can modify the `if __name__ == "__main__":` block in `mission_simulator.py` or use a one‑liner from the terminal.  Example one‑liner that runs an endurance mission with a different environment and wear rate:
```bash
python3 - <<'PY'
import mission_simulator as ms
cfg = ms.MissionConfig(environment="standard_normal_altitude")
sim = ms.MissionSimulator(cfg, dt_s=1.0, seed=42)
# Run full mission with 1%/hour wear drift
sim.run_endurance_mission(wear_pct_per_hour=1.0)
sim.save_mission("standard_mission.json", "Standard‑day ISR sortie")
PY
```
You can also inject other faults via `sim.set_fault("oil_pressure_psi", percent=-30, ramp_s=8)` or change stage durations by passing a `stage_durations_s` dict to `MissionConfig`.

## Real‑time UI

A realtime control-room UI is provided under the **frontend** folder. The backend advances the simulator one timestep at a time, so operator commands affect the running mission rather than a precomputed replay.

It supports:
* Selecting any of the six environmental presets before start.
* Editing the duration of every mission stage before start.
* Enabling endurance wear with a configurable percentage drift per hour.
* Setting and clearing signed percentage faults on every telemetry channel while the mission is running.
* Live RPM, altitude, ambient temperature, expected values, actual values, deviations, trends, active faults, and event timeline.
* Pause, resume, playback speed, reset, and JSON mission storage.

### Run the UI
From the repository root:
```bash
cd /home/akshat/Desktop/SIH_UAV_Simulation
python3 -m pip install flask   # install Flask if not already present
python3 frontend/app.py       # starts the server on http://localhost:5000
```
Open `http://127.0.0.1:5000` in a browser. Configure the mission, click **Start mission**, then use **Manual fault** while it is running. A cleared fault ramps back toward zero; the event timeline records every operator action. Use **Save mission** at any point to write a complete JSON file under `missions/`.

For a shorter interactive demonstration, set the stage durations to values such as 10, 10, 10, 20, 40, 10, 10, and 10 seconds before starting.

The UI displays time, stage, RPM, altitude, ambient temperature, and oil‑pressure information in real time on a canvas.

## Selecting and changing datasets

The UI has a **Dataset** selector. Dataset files live in `datasets/` and are loaded when the Flask server starts. The included `rotax914_baseline_dataset.json` is the default. To add a future dataset, copy that file, change its `dataset_id`, label, stages, environments, or fluctuation settings, and restart the server. No frontend or simulator code changes are required.

Each dataset must use `schema_version: 1` and this structure:

```json
{
   "schema_version": 1,
   "dataset_id": "my_dataset",
   "label": "Human-readable dataset name",
   "fluctuation": {
      "oil_pressure_psi": [0.02, 0.85]
   },
   "environments": {
      "normal": {
         "isa_dev_c": 0,
         "cruise_altitude_m": 2500,
         "airfield_elevation_m": 300,
         "label": "Normal conditions"
      }
   },
   "stages": [
      {
         "name": "GROUND_IDLE",
         "rpm": 1400,
         "throttle": 0.08,
         "afr": 14.7,
         "altitude_frac": 0,
         "default_duration_s": 120
      }
   ]
}
```

`fluctuation` values are `[sensor_noise_fraction, smoothing]`. Dataset IDs must be unique. Invalid files are ignored by the selector and can be diagnosed by checking the server log or the `/api/datasets` response.
